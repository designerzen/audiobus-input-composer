# T096 — Retrieval-augmented symbolic composition

Family: **Learned symbolic models and adaptation**. Reviewed 24 November 2026. [Technique index](README.md).

## Mechanism

Retrieve relevant source fragments and transform or combine them for the current context.

## Proposed symbolic-music use

Search a provenance-preserving library by contour, rhythm, harmonic role and user-approved tags.

## Worked example or experiment setup

Retrieve an answering cell with the same ending function, transpose it deliberately and trim only within its declared duration contract.

## Time, emotion and energy

Emotion biases tags as hypotheses; energy filters density; time chooses eligible phrase roles and recency.

## Failure modes and practical limits

Similarity is not quality, and retrieval can repeat sources too literally. Source licensing and attribution remain separate questions.

## Evaluation

Compare retrieval relevance, join quality and motif repetition against authored random cell selection.

## AudioBus integration

Keep learned output behind deadlines and the same score validator as procedural output. Document model/corpus provenance and retain a procedural fallback.

Produce resolved musical events before delivery. The [composer architecture](../11-composer-architecture.md), [Plutchik interface](../18-plutchik-interface.md) and [scheduling contract](../12-audiobus-events-and-scheduling.md) supply the shared context. This is research, not an implemented Input feature.
